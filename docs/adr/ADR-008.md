# ADR-008 — Separate waking from interrupting

Status: accepted anticipation design.

Context: an event can matter without justifying an immediate user interruption.

Decision: persist intentions, derive stable wake identities, then record attention decisions with quiet hours, notification budget, workload, and readable reasons. Batch produces a digest; schedule re-arms rather than pretending work completed.

Consequences: duplicate observations resume once and suppression is measurable. User-facing action is not implied by merely matching a trigger.

When to use: follow-up work after repository changes, responses, process events, or other supported triggers.

Do not use: a wake as authorization or quiet-hours bypass. See [anticipation](../concepts/anticipation.md).
