# ADR-004 — One actor, one writer

Status: accepted storage boundary.

Context: concurrency and isolation require explicit ownership of log ordering and encrypted storage.

Decision: one writer owns each actor’s ledger and LMDB transaction stream. Actors have separate namespaces, keys, projections, and indexes. Authenticated actor capabilities do not grant admin access.

Consequences: clients share the daemon; embedded and stdio modes are alternative owners. Shared actor directories across processes are unsupported.

When to use: design deployment topology and actor boundaries.

Do not use: file sharing or a second embedded process as multi-writer coordination. See [deployment](../guides/deployment.md).
