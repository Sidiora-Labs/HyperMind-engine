# Recall and activation

Recall reads indexed evidence; activation composes context for a conversation and question. Both expose provenance and health rather than pretending missing sources were available.

The planner combines lexical, vector, entity, temporal, graph, relation, and belief lanes where available. Identifiers favor entity lookup; temporal questions use windows; how/why queries can include procedures. The relation lane ranks relationships directly from their own embedding lane, alongside document and entity retrieval; the graph lane keeps its relation-term gating and follows an edge only when its relation name shares a literal token with the query or resolves, by exact normalized name, to the same relation term as the query in an imported vocabulary version, so reviewed alias names widen matching while fuzzy similarity never gates retrieval. Reciprocal-rank fusion combines rankings, not incompatible raw scores. Embedding-space identity includes model, revision, dimensions, and role. The entity lane also indexes externally observed repository snapshot frames alongside messages, so file paths and symbol names become entity postings; lexical indexing is deliberately not extended to those frames because activation can only decode message kinds into bundle items.

Answer feedback adjusts a bounded actor-local ranking preference that is applied after the composite score, never inside it. Attesting the evidence behind an answer moves a per-LSN weight toward the disposition's target, and that weight can raise or lower a candidate's fused score by at most a quarter in either direction. Evidence with no feedback stays exactly neutral, so a store with no attestations ranks identically to one that never had preferences. Ranking preference is never evidence authority: it reorders candidates and cannot change item content, provenance, or what the ledger says happened.

The ten activation tiers are resident, intent, bindings, work ledger, prospective, conversation, entity, conflicts, fused, and temporal. The first four are required. Optional context shrinks before required bindings. If required content exceeds budget, the engine narrows the subtask and reports a gap. Deadline fallback is explicitly degraded with staleness information.

A minted memory is a summary, so each surviving summary hit in the fused tier is paired with the original observation it cites: broad topic matching is followed immediately by the precise evidence in its own item, carrying the original record's authority and the single cited LSN, and the pair is kept or dropped together.

The retrieval manifest carries five lists of ledger positions. `candidates` are the positions the lanes offered, `selected` are the positions retrieval kept from them, `included` are the positions whose text actually survived trimming into the bundle, `used` are the positions a later attestation confirms the answer relied on, and `support` is the evidence that produced a derived claim. Support is filled only from surviving summary items and their paired evidence, so it answers what a minted memory was built from rather than what text merely appeared in context; a summary that trimming removes contributes no support. A position can appear in both `included` and `support`, and neither list is derived from the other.

The core activation path performs index reads and no model calls. Optional query embedding is distinct from rebuilding document embeddings. Explicit reconstruction is a separately requested model-backed operation, not ordinary recall or observed evidence.

An experimental geometric alignment boost can rescale already-fused scores: candidate vectors and the query are projected onto a basis taken from the highest-ranked candidates that have a stored vector, and each score is multiplied by the resulting alignment factor. It is off by default, it never runs in the core activation path, and candidates without a stored vector stay neutral rather than being dropped. Enabling it for a deployment requires an explicit deployment identifier, a declared geometry version, and evidence produced by hm-eval whose measured boosted MRR@10 exceeds its baseline; an unqualified deployment is refused, not silently ignored. This is the same rule the optional cross-encoder rerank already follows.

The graph mode of `recall` is a separate read over the repository graph rather than a lane of the planner. It walks the validated relationships of the published generation from an anchor node, which is either a node id in hex or a repository name plus a node name that the surface resolves across the six fact kinds. Each item names the relation, the direction, the endpoint node, the evidence-counted weight, the validity interval and the asserting event, and carries `derived_inference` authority with the provenance of the relationship event and of every snapshot line it cites. The traversal is bounded at 256 neighbours, `filters.temporal_from_ns` fixes the validity instant so an as-of walk is possible, and an anchor that matches no visible node returns an ok envelope with an explicit gap rather than an empty answer that looks like one.

When to use: `recall` for bounded evidence lookup, `activate` for whole-turn continuity and token limits, and timeline/as-of access for history.

Do not use: lexical-only output as proof of semantic retrieval, omit gaps from your client, or confuse ranking with evidence authority. Preserve actual encoder/retrieval identity in benchmarks.
