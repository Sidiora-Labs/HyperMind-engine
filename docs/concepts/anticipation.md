# Anticipation

Use `intend` when an objective should resume after a named event. Do not use it as proof that the objective has completed. An intention is durable before waiting, and a stable wake ID prevents the same observed event from resuming it twice.

Triggers cover time, schedules, child completion, process exit, file or repository changes, channel messages, external conditions, user responses, entity mentions, loop closure, resolved predictions, and belief changes. `cancel_intention` cancels an existing intention. `evaluate_wake` cites a persisted observed-event LSN; it cannot substitute a caller-authored event description for evidence. Scheduling re-arms a distinct intention with a future deadline.

Every fired intention records an attention decision and reason. Quiet hours produce a batch digest, duplicate wakes are suppressed, notification budgets are enforced, and high workload schedules a later attempt. Only `notify`, `ask_user`, and `start_work` appear as individual prospective items. Batched items appear together in the next conversation bundle. `inspect` on `hm://ACTOR/attention` exposes the bounded history and reasons.

Use `predict` before an operation to fix its bounded expected predicates. Use `outcome` afterward with observed-event LSNs, not with a narrative assessment. Assessments are supported, contradicted, pending, unresolvable, or not executed. Memory and reconstruction are not observed evidence. Three consecutive failures of one mechanism produce a `revision_required` gap; there are at most two revision rounds and five observation probes. `hm://ACTOR/calibration` reports counts per predicate kind. These are outcome frequencies, not probability-calibration scores: predictions currently carry uncertainty text, not numeric probabilities.

Closed, independently observed tool/effect chains can support a learned procedure. Three independent roots in two conversations are required for the supported state. Tentative and supported procedures render as observations. Only a user-authorized adoption makes one an instruction.

## Evaluation

Task 7.6 measures the production attention function against the checked-in, hand-labelled policy regression cases, including quiet hours, duplicates, exhausted budgets, workload, and worthwhile interruptions. This synthetic policy set is not a claim about measured user-interruption preferences. The gate requires suppression precision of at least 0.90, reports the confusion counts and suppression recall, and requires a reason for every decision. Calibration runs through the real actor and MCP tools using filesystem/process observations, all seven predicate kinds and all five assessments, duplicate replay, and restart.

HNSW recall parity uses the same seeded int8 vectors as the index qualification test, with 50,065 vectors and 100 queries. It is reported separately from the public benchmarks' retrieval identity; synthetic vectors are not a semantic encoder.

The public runs use the pinned full 500-question LongMemEval-S cleaned split and all 1,986 LoCoMo10 questions. Reader input contains only question metadata and content retrieved from a real HyperMind ledger. Reference answers and annotated evidence are available only to scoring. LongMemEval uses its pinned upstream category-specific judge prompts. LoCoMo's upstream F1 scorer is retained unchanged, including its Python dependencies and separate license; optional pinned-judge accuracy is reported separately and never blended into F1. Both all-category and non-adversarial LoCoMo metrics are retained. No missing-data or partial-coverage run qualifies.

Run `cargo run -p hm-eval -- bench longmemeval --live` or `bench locomo --live` only with explicit provider-spend authorization, `CENTRA_GATEWAY_URL`, and `CENTRA_GATEWAY_API_KEY` in the environment. Both reader and judge use the user-selected `openrouter/openai/gpt-5.6-luna` through that gateway; they do not connect directly to OpenRouter. `provider-check` makes one small, budgeted request per distinct configured model. Without `--live`, benchmark requests must replay content-hash caches. All reader and judge calls share a durable $49 ceiling in `eval/cache/slice7-gateway`, leaving $1 of the authorized $50 for prior small provider tests. Reservations precede dispatch, unknown attempts retain their reservation, and request/response metadata records model, tokens and costs. Cache directories must not be deleted or changed to reset a spending limit.

The reader packs complete source passages from the top 128 real lexical chunks within an 80,000-character serialized excerpt limit. It preserves source role, date, session and exact ledger/source byte spans, prioritizes primary statements with session diversity, and retains relevant assistant material. Compact source/session references in the model input map to full citations in the answer record; repeated ledger URIs and dataset hashes do not consume the model's excerpt budget. Coverage reports distinguish candidate and included sessions, role characters, partial documents, and omitted oversized passages. This is lexical retrieval, not a semantic encoder or a guarantee that all supporting evidence was retrieved.

Luna reader and judge requests use `reasoning_effort: medium` with respective `max_completion_tokens` limits of 4,096 and 2,048, including reasoning and visible output. The small provider check uses `none` and 10 tokens. Incomplete completions fail closed without automatic retry. Both wire caches and reader-answer identities bind these settings; earlier responses cannot silently qualify the new request policy. The exact model route is pinned, but Centra's catalog does not identify an immutable dated snapshot. Reports retain the returned model identity and cached wire responses; they do not claim snapshot reproducibility that the gateway has not supplied. Earlier GPT-4 responses remain in their original content-hash namespaces and budget accounting, and are never included in a Luna score.

Use `diagnose longmemeval --questions ID,ID [--live]` for one to 32 preselected questions and `rejudge longmemeval ID PREDICTION_PATH [--live]` to evaluate an unchanged saved Luna answer with the official judge prompt. These write separate diagnostic reports, never qualify the full benchmark, and share the original spending ledger. Diagnostic results are not an accuracy estimate for all 500 questions.

Responses lacking a dollar-cost field retain their conservative reservation unless the user has explicitly confirmed upstream rates. With that confirmation, recorded token usage can be reconciled at those rates under a separately labeled accounting basis; it is not a gateway-reported invoice. Unknown calls retain reservations. Set the same gateway URL for offline replay because caches bind the endpoint. CI uses the `CENTRA_GATEWAY_URL` repository variable (default `https://gateway.centra.ag/v1`) and receives no API credentials. Routing changes never silently reset historical accounting.

`cargo run -p hm-eval -- gate slice7` requires full coverage, LongMemEval accuracy of at least 0.90, LoCoMo non-adversarial F1 of at least 0.75, attention precision of at least 0.90, and HNSW recall parity of at least 0.98. It writes measured results, including failures, rather than treating an unavailable public benchmark as a pass.

The CI merge gate makes no paid requests. It requires the `slice7-public-evidence` artifact from the explicitly pinned `SLICE7_EVIDENCE_RUN_ID` repository variable. The artifact's root is `eval/`: include the pinned datasets and `cache/slice7-gateway` response/budget files; actor stores can be rebuilt. Missing evidence fails the gate. Provider credentials must never be included. A local run does not establish that this hosted CI gate passed.
